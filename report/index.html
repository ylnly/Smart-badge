产品定位

可佩戴的二次元 AI 陪伴徽章：活在圆屏里，能看你、听你、陪你。

💫

核心命题

传统吧唧是“印着角色的铁皮”，我们要交付“角色本人住在里面”。

🔌

离线优先

断网也有完整体验，联网后解锁 LLM 自由对话。

🧠

本地 ASR

FunASR Paraformer 中文识别，运行于电脑端 RTX 5070，离线可用，不调用云端 ASR。

💬

云端 LLM

经云端 API 调用，角色卡 + 对话历史约束回复；密钥不进固件/日志。

🔊

本地 TTS

CosyVoice 3.0（GPT-SoVITS 备选），HTTP API，仅监听回环地址，不回退云端。

📡

通信协议

WebSocket 半双工双向通信，17 种消息类型，按 session/turn 区分轮次。

📇

角色卡系统

YAML/JSON 与代码分离，30+ 字段约束性格、措辞、音色与禁止行为。

🔋

开发板

ESP32-S3-Touch-LCD-1.85B：360×360 屏、双麦、扬声器、IMU、WiFi/BLE。

开发阶段

七步走通语音闭环

严格分阶段实施，每个阶段先验收再进入下一阶段，不一次性生成大量未验证代码。

阶段一

本地 ASR 验证

环境检查 + 独立虚拟环境 + FunASR Paraformer 中文识别，建立性能基线。

阶段二

云端 LLM 验证

统一 LLM 客户端封装，测试角色卡遵循、首 token 延迟与限流处理。

阶段三

本地 TTS + 对话服务

评估 CosyVoice 3.0，建本地 TTS HTTP 接口，接通 ASR+LLM+TTS 最简闭环。

阶段四

WebSocket 通信

定义统一消息协议，完成客户端模拟器，测试上传/下发/中断/重连。

阶段五

ESP32-S3 固件

Wi-Fi 连接、麦克风采集、按键、音频播放、WebSocket 与 LCD 状态显示。

阶段六

整机联调

从录音到播放完整跑通，测多轮对话、网络中断与服务异常，记录延迟。

阶段七

稳定性与性能优化

依真实数据优化模型与参数，评估流式 ASR/LLM/TTS，查显存与长稳。
